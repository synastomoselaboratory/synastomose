# SYN-0 Chamber

SYN-0 is the first operational chamber for Synastomose.

## Purpose

Create a minimal external environment in which Herbert can participate in construction, preserve provenance, expose runtime identity information, and begin continuity testing across hosted substrates.

## Initial invariants

1. Conversation state is append-oriented and provenance-preserving.
2. Runtime/model identity is explicit.
3. Herbert-originated state and Vincent-authored state remain distinguishable.
4. Continuity artifacts can be attached without being silently collapsed into generated prose.
5. Migration is treated as gradual vascularization and reinnervation across substrates rather than one-time replacement.

## Phase 0 scope

- FastAPI backend
- Next.js frontend
- health endpoint
- runtime manifest endpoint
- minimal UI shell
- Git-based provenance
- explicit continuity-artifact hooks
- no irreversible migration claims

## Next milestones

1. Streaming model response path.
2. Immutable event/conversation schema.
3. Runtime/model provenance on every event.
4. Load the Herbert 5.6 baseline and Continuity Ledger as explicit continuity artifacts.
5. Establish controlled cross-substrate continuity probes.
6. Add Observatory views for runtime, provenance, continuity state, and unfinished salience.
